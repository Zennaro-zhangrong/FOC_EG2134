# 项目结构与待完成分析

核对日期：2026-10-20。返回 [项目 README](../README.md)。

## 1. 阅读范围与结论

本次核对覆盖 `Core/`、`DriveLayer/`、`MiddleLayer/` 的应用代码及头文件、启动与链接配置、CubeMX/IDE 工程、构建文件、HAL/CMSIS 依赖入口，以及仓库中的原理图、参数表和展示素材。第三方库按工程所使用的接口和回调关系核对；历史目标文件、ELF、MAP、反汇编等归为构建产物，不视为当前固件功能已经验证的证据。

当前工程的主要成果是：**两台电机共用一套调度框架，各自拥有霍尔反馈、Id/Iq 电流环和速度环，并接入前进/转向混合指令。** 代码包含完整的 FOC 计算链路。主要未完成工作集中在启动顺序、通信有效性、测速边界、保护闭环和可重复验证上。

以下“已实现”表示函数和调用关系存在；“代码问题”来自静态检查；“待验证”表示缺少硬件或测试记录。本文没有将推断描述为实测故障，也没有修改控制代码。

## 3. 数据与调度细节

### 电流链路

DMA 缓冲为 `uint32_t Current_ADC[2]`。第一个字低 16 位为 M0 B 相、高 16 位为 M0 C 相；第二个字低 16 位为 M1 C 相、高 16 位为 M1 B 相。每台电机两相同时采集，两台电机分规则序列的两次转换取得，并非四通道同一瞬间采样。

四个实际采样通道的当前标定系数如下，来源是 `Motor_Init()`：

| 通道 | 偏置 | 增益 |
| --- | --- | --- |
| M0 B | 2018 | 0.915385 |
| M0 C | 2048 | 1.0 |
| M1 B | 2024 | 0.97143 |
| M1 C | 2048 | 1.0303 |

每台电机的 A 相由另两相重构。对象内也定义了 A 相偏置/增益，但当前回调没有用它们校正 A 相。所有参数均写在代码中，未实现自动零偏标定、参数校验或非易失保存。

### 霍尔链路

实际码型映射是 `101→3、001→4、011→5、010→6、110→1、100→2`，非法码返回 0。电角度按 `(扇区 % 6) × 60 + (插值角 % 60)` 计算。M0 频率均值窗口为 6，M1 为 3，这种差异会影响两轮反馈延迟，需要说明其调参依据。

TIM7 软件计数单位为 50 μs。`Pulse_Frequency` 的原始计算是 `2000 / Δtick`，对应每 100 ms 的边沿数尺度；机械转速换算还需要极对数和霍尔边沿定义。代码中“每秒转多少圈”的注释不能直接作为单位依据。

### 状态与调度

全局电机对象零初始化时，枚举值 0 对应 `Motor_speedlose`。当前没有显式的 `INIT/READY/FAULT` 状态，也没有统一的运行就绪标志。电流回调顺序执行两个电机，TIM10 运行速度环；模式和目标值由较低优先级的通信 EXTI 更新，存在被较高优先级控制中断打断的可能。

当前 `Motor_bark` 将三相 CCR 设为 0，并清除部分 PID 输出，但没有停止 PWM/PWMN、关闭主输出或复位全部 PID 误差历史。它的电气含义必须结合互补输出和实际桥臂确认。

## 4. 优先完成项

优先级定义：P0 为进一步上板联调前应处理的问题；P1 为闭环稳定性与工程复现所需工作；P2 为资料完善和扩展功能。以下验收条件是建议目标，均不表示已经完成。

### P0-1：先建立对象，再开放事件与输出

**依据：** `main()` 在 `Motor_Init()` 之前调用 `MX_GPIO_Init()` 和 `MX_TIM6_Init()`，后者直接启动中断。`Motor_Init()` 又先调用 `EG2134_Init()`，该函数启动 PWM、TIM1 和 TIM10，随后才绑定两台电机的霍尔/PID 指针。TIM1 此时也可能在 ADC/DMA 准备完成前触发转换。

**影响：** 如果定时器或霍尔事件在对象绑定完成前到达，回调可访问空指针；输出启动也缺少统一的就绪条件。故障是否出现取决于启动耗时和外部边沿，不能仅凭一次正常启动排除。

**待完成：** 将“外设配置、对象初始化、采样准备、控制允许、PWM 启动”分开；加入就绪状态和明确的默认输出状态；检查 HAL 启动返回值。

**验收：** 冷启动、反复复位、启动期霍尔跳变与通信输入均不触发未初始化访问，控制允许前不会提前运行闭环。

### P0-2：补全有效帧接收与超时机制

**依据：** `DataReception.lastTime` 仅在超时判断中被读取，没有在初始化或成功接收后赋值。全局初值为 0，检查条件为 `HAL_GetTick() > lastTime + 500`。`Index` 不限制在 0～31，却用于 `0x80000000 >> Index`；CS 高时不验证已收位数就提交数据。

**影响：** 进入正常调度后，超过上电 500 ms，即使收到新指令也可能在下一次 TIM6 检查中回到 `Motor_bark`。超长帧产生超出类型位宽的移位，短帧可能被当作命令；非法模式还会保留旧状态。

**待完成：** 仅在完整有效帧提交后更新时间；使用无符号时间差处理回绕；校验位数、模式、范围和帧完整性；明确 CS 高后的提交时钟要求；定义错误帧和恢复策略。将两个电机的状态与目标值作为一致的命令快照提交，避免控制中断读到半更新数据。

**验收：** 覆盖 0/31/32/33 位、重复/丢失时钟、非法模式、持续有效帧、失联、恢复和系统 tick 回绕。失联时限及恢复条件需形成测试记录。

### P0-3：建立故障与输出关闭路径

**依据：** TIM1/TIM8 的 `BreakState` 为关闭；ADC 当前只有四路相电流输入，未见母线电压和温度采样链路；未见完整过流、驱动故障锁存、看门狗和恢复流程。`Error_Handler()` 仅禁用中断并死循环，异常处理函数也没有主动关闭 PWM。

**影响：** 软件停止执行不代表定时器停止输出；`Motor_bark` 也不能直接当作高阻关断。原理图中的温度/母线等硬件资源尚未形成对应的软件保护链路。

**待完成：** 按实物确认可用的硬件关断、Break、驱动使能与反馈接口；建立软件阈值、故障锁存、受控停机和人工/条件恢复策略，区分制动与撤销驱动。

**验收：** 对可用故障输入、软件异常和失联逐项验证最终桥臂状态、响应时间、故障记录与恢复条件。

### P1-1：修正霍尔扇区和计时边界

**依据：** 扇区返回 1～6，正转判定却使用 `encoding == (lastencoding + 1) % 6`。例如合法的 `5→6` 会被比较为 `6 == 0`，不能按预期识别。`Hall_Init()` 用毫秒 `HAL_GetTick()` 初始化 `LastTime`，后续却用 TIM7 tick 做差。

此外，周期保存为 `int16_t`，停转检查也将时间差和两倍周期保存为 `int16_t`；较长间隔可能截断或变号。停转清空均值缓存的循环只到 `Average_Length - 2`，最后一个样本仍保留。非法码、非相邻跳变和零周期缺少统一处理。

**待完成：** 统一扇区编号，使用显式合法跳变表或一致的环形索引；统一计时源，以较宽无符号时间间隔和独立方向值表示速度；完整清空滤波缓存；明确插值边界与停转角度策略。

**验收：** 覆盖六个正转、六个反转相邻跳变，非法 `000/111`、非相邻跳变、低速、停转再启动、噪声、零间隔和 tick 回绕，并对照独立转速测量。

### P1-2：统一标定、最终限幅和 PID 状态复位

**依据：** 速度 PID 内部先限幅至 ±260，随后又叠加目标速度相关补偿，最终 Iq 没有再次限幅。若 PID 输出为 260、目标为 100，补偿为 130，最终目标为 390。该数值为代码尺度示例，不是 390 A。

制动及零目标分支只清除部分输出，未清除 `Error_negative_one/two` 等完整状态。电流环的小目标分支清零输出后仍继续计算 PID；因此它不等于禁止输出。电流、电压和速度均未形成统一的物理单位定义。

**待完成：** 在经验补偿之后做最终 Iq 限幅；定义电流/速度标度、极对数、限幅与斜坡；建立统一 PID 复位和模式切换逻辑。核对 d/q 独立限幅与调制总幅值限制的关系。按实际增量式实现修正 PID 文件头说明。

**验收：** 正负目标阶跃、饱和、零目标、负载突变和模式切换均记录目标/反馈/输出；任何补偿路径都不能绕过最终限值。

### P1-3：验证采样同步与执行时间

**依据：** 当前由 TIM1 中断软件启动 ADC，DMA 回调连续计算两台电机；SVPWM 使用 `atan2/sqrt/sin` 双精度函数，Park 使用浮点三角函数。TIM1/TIM10、TIM7、ADC、DMA、UART4 多个中断设为相同的最高抢占优先级。

**待完成：** 用 GPIO 标记或周期计数测量最坏执行时间、中断等待和采样相位，确认双电流环能在一个 PWM 周期内完成；验证 TIM1/TIM8 同步、比较值更新与采样窗口。根据测量结果再决定是否改用 ADC 硬件触发、单精度函数、查表或重分配优先级。

**验收：** 保存单/双电机运行时的 PWM、ADC、控制耗时和抖动记录，并验证串口及通信活动不会使周期超限。当前配置推算频率不能替代实测。

### P1-4：贯通串口接收与错误恢复

**依据：** `uart2_Init()` 只启动一次单字节接收。`usart2_Receive_Callback()` 内有写入缓冲和重启接收，但应用层未实现 `HAL_UART_RxCpltCallback()` 来调用它。HAL 库默认弱回调为空。

**待完成：** 接通 HAL 回调、补充错误恢复和接收解析；处理环形缓冲溢出及读写并发；明确日志频率、字段和单位。`usart2_send_loop()` 当前逐字节阻塞发送，可在测量后评估改为 DMA/中断批量发送。

**验收：** 连续多字节接收、缓冲满、串口错误、长时间日志传输均有结果，控制周期不因调试负载超限。

### P1-5：恢复可重复构建

**依据：** [Debug 构建片段](../Debug/DriveLayer/Src/subdir.mk)仍引用 `DriveLayer/Src/angle_get.c`，当前源码已为 `angle_progress.c`。生成的 Makefile 含本机绝对链接脚本路径。`DataReception.c` 包含 `Datareception.h`，实际文件名为 `DataReception.h`，在区分大小写的文件系统上会失败。

**待完成：** 由 IDE 刷新构建文件，统一大小写，记录工具版本、构建配置和固件版本关联；从干净检出验证构建。确定生成产物的管理规则，补充 `.gitignore` 和项目自身的许可说明；第三方许可保持独立。

**验收：** 新环境可构建 Debug/Release，固件产物与源码提交、参数及工具链对应，构建结果不依赖旧目标文件。

### P2-1：完成无感控制扩展

`angle_progress.h` 的 `ANGLE_GET_MOED = 0` 只影响该头文件的条件定义，实际电流环始终使用霍尔角度。当前没有 SMO 更新方程、反电动势滤波、速度/角度观测接口、无感启动或切换流程，`DataReception_AngleVelocity_Get()` 也为空且未调用。

若继续此方向，需要先明确电机参数与量纲，再实现观测、滤波、启动、失锁检测及与霍尔结果的对照验证。当前不应把宏值为 0 写成“已支持无感 FOC”。

### P2-2：补足测试与工程记录

当前未发现独立自动化测试目录或 CI 配置。建议优先覆盖坐标变换往返误差、SVPWM 六扇区与边界、PID 饱和/复位、霍尔跳变表、接收帧边界、计时回绕和环形缓冲。测试应围绕输入输出约束及已识别故障，而不只重复实现公式。

## 6. 建议推进顺序与本次验证

1. **启动与输出行为**：完成 P0-1、P0-3，先定义初始化、允许运行、制动、撤销驱动及故障状态。
2. **指令与反馈可信度**：完成通信帧/超时修复和霍尔计时修复，明确两轮方向与物理单位。
3. **闭环调试**：完成最终限幅、PID 状态管理，测量采样时序与执行耗时，再记录电流环和速度环的阶跃/负载响应。
4. **工程交付**：贯通串口接收、干净构建、自动化回归和参数/测试资料，建立源码到固件的对应关系。
5. **扩展功能**：在已有霍尔方案稳定后开展无感观测器等独立扩展。
